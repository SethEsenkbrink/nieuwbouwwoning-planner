## Vier bugs, alle vier van mij

### 1. `npm audit`: 15 high severity

Alle vijftien uit één devDependency, `@netlify/vite-plugin`. Twee echte oorzaken
(`brace-expansion` DoS, `sharp`/libvips), dertien doorvertalingen. Gecontroleerd met
`npm ls --omit=dev --all`: **niets ervan zit in de productiebundle.**

`npm audit fix --force` zou `@netlify/vite-plugin` van 2.12.9 naar 2.1.4 downgraden —
elf minor versies terug om een dev-only DoS op te lossen. In plaats daarvan `overrides`
in `package.json` → 0 vulnerabilities, nieuwste plugin blijft. Vastgelegd in **ADR-0007**.

### 2. CSP met newlines → dev-server crashte bij élke request

De Content-Security-Policy stond als gewone TOML-multiline string (`"""..."""`), die
newlines behoudt. HTTP-headers mogen die niet bevatten:

```
TypeError: Headers.set: "..." is an invalid header value
```

Opgelost met TOML's backslash line-continuation — één regel in de waarde, leesbaar in het
bestand. Alle drie de varianten door een echte TOML-parser gehaald om te bevestigen dat
dit geen parser-eigenaardigheid is.

Nieuw: **`npm run verify:headers`** (`scripts/verify-headers.mjs`, in `npm run verify`).
Valideert elke header met Node's eigen `Headers.set()` — dezelfde validatie als de
emulator — plus: alle 7 kern-directives aanwezig, alle 4 Firebase-endpoints in
`connect-src`, en géén `'unsafe-inline'` in `script-src`. Negatief getest op alle vier de
scenario's. Vereiste een nieuwe devDependency: `smol-toml` (206 kB, geen eigen deps).

### 3. Witte pagina bij ontbrekende config

`src/lib/firebase.ts` gooit bij het laden van de module een fout als de config ontbreekt.
Bij een statische import gebeurt dat vóórdat React kan renderen → witte pagina, melding
alleen in de console.

`main.tsx` importeert `App` nu dynamisch binnen een `try/catch`, met een
`OpstartFout`-scherm dat vertelt wat er moet gebeuren. Als eigen chunk gebundeld, dus
alleen geladen als het misgaat.

### 4. Productie-CSP gold ook in dev → lege pagina, geen melding

De ergste van de vier, omdat hij zichzelf verborg. `@netlify/vite-plugin` past de headers
uit `netlify.toml` ook lokaal toe. Onze CSP staat geen inline scripts toe, maar Vite heeft
die nodig: `@vitejs/plugin-react` injecteert een inline preamble voor Fast Refresh, en de
HMR-client verbindt over `ws://localhost`. Beide geblokkeerd → élke component-module gooit
bij het laden een fout. En omdat het foutscherm uit bug 3 zélf een React-component is, kon
ook dát niet renderen.

De plugin-optie `headers: { enabled: false }` staat in de types maar **doet niets** in
v2.12.9 — geverifieerd met `curl`: de CSP stond er gewoon nog. `middleware: false` zou ook
de emulatie van Netlify Functions uitzetten, die we nodig hebben voor de documentparser.

Opgelost met een eigen Vite-plugin `stripCspInDev` (tien regels, `apply: "serve"`) die in
dev precies één header verwijdert. Met curl bevestigd dat X-Frame-Options,
Referrer-Policy en Permissions-Policy intact blijven.

**Gevolg:** de CSP geldt lokaal niet meer. Test CSP-wijzigingen op een Netlify deploy
preview; `verify:headers` bewaakt ondertussen de syntaxis.

## Productrichting bepaald — de kernfeature

Seth zit in de fase met een **indicatieve** opleverdatum die voortdurend schuift. Elke
verschuiving veroorzaakt een cascade richting de partijen die hij zelf heeft ingehuurd
(keuken, tegels, vloer, stukadoor, waterontharder, verhuizing), en dus veel mailverkeer en
handmatig omrekenen.

Doorgesproken en vastgelegd. De kern is niet planning maar **synchronisatie**: het verschil
tussen de datum die jij weet en de datum die elke partij afzonderlijk denkt te weten. Dat
verschil ís de actielijst.

Vijf ontwerpprincipes, uitgewerkt in **ADR-0008**:

1. Een opleverdatum heeft een **staat** (indicatief / bandbreedte / aangezegd) en is een
   **band**, geen enkele waarde.
2. Afspraken hangen aan een **anker + offset**, nooit aan een vaste datum.
3. Per betrokkene: **aanlooptijd** × **annuleertermijn** → het laatste moment waarop je nog
   gratis kunt schuiven.
4. Per betrokkene een **communicatieregel** — dit haalt naar verwachting het grootste deel
   van het mailverkeer weg.
5. Het verschil tussen berekende en **gecommuniceerde** datum is de actielijst.

Bijbehorende domeinkennis (droogtijd dekvloer, opzegtermijn huidige woning, geldigheid
hypotheekofferte) staat in `docs/2026-07-29-betrokkenen-standaardlijst.md`, met per
categorie realistische startwaarden.

`PROJECT.md` §5 en §6 zijn bijgewerkt: datamodel uitgebreid met `ankers`, `betrokkenen` en
`afspraken`, en de featurevolgorde herzien — deze module gaat vóór de fase-tijdlijn.
